5Architecture Map

  • Frontend: static Vite 6 app, vanilla JS (one devDependency: vite). No framework, no TypeScript, no tests, no lint, no CI. Netlify serves; SPA fallback rewrite /* → /index.html.
  • ⚠ Generated-code pipeline (the biggest integration landmine): the Netlify build runs python build-netlify-app.py before vite build. That script overwrites app/index.html, app/src/main.js, app/src/site-header.js, app/src/fallback.js, app/src/main.css from templates whose real source of truth is build-embed-one.py (1,600 lines of Python holding the JS/CSS as strings, plus every Webflow CDN URL). auth.js, shop.js, decrypt.js + their CSS are authored directly and are safe to edit. Any backend integration written into the generated files is silently destroyed on the next deploy. Integration must go through the authored files + the existing CustomEvent bus, or the generator itself must be changed with Tiardt.

7Scale Assessment

  • Target: DECIDED (24 Aug, Vitaley): 100,000 simultaneous active users. This is the design and load-test bar, chosen deliberately above the expected launch-day reality so the margin is engineered in rather than hoped for. YouTube first-hour analytics still get pulled to model the realistic arrival curve as the scenario shape; 100k concurrent is the pass bar.
  • What 100k simultaneous actually stresses: the video CDN is built for exactly this and delivery cost is driven by minutes watched, not concurrency — 100k concurrent watching the 51-minute library costs roughly the same to deliver as 100k spread across a day. The pressure lands on OUR layers: the checkout/webhook surge, auth session creation bursts, entitlement checks at playback start, and the wall. Design consequences: entitlement decisions cached into short-lived signed playback tokens (no DB hit per play), stateless API behind autoscaling, queue-and-drain on webhook ingest, static-first everything else, and the wall degrades gracefully (read-only) before anything touches payments, login, or playback.
  • What we know: launch library = 51 minutes (36+15), audio "a few minutes", monthly drops after. The static front end on Netlify's CDN is effectively load-indifferent; the pressure concentrates in auth burst, webhook ingest, entitlement checks at playback start, and the wall — none of which exist yet, so the load model can be designed in, not retrofitted.
  • Cost drivers (verified vendor rates, Aug 2026): Cloudflare Stream $5/1k min stored, $1/1k min delivered → 51-min library ≈ $5 storage; 100k full-watches ≈ $5.1k delivery in launch month; Matt's 30/60-min bands remain the right frame. The "3-hour videos" job-post claim, if real, multiplies this 3–6× — verify (ST-7).
  • Load-test plan: tiers per Matt's plan (1 real → hundreds → thousands → agreed viral tier), each layer measured independently; test the arrival curve from YouTube analytics once access lands.

8Anti-Fragility Assessment

Today there is nothing to fail — and nothing to degrade to. The controls below are required in the build, not the audit:

  • Webhook ingestion: signature verification, idempotency on payment events (replay must grant once), dead-letter visibility, bounded retries.
  • Entitlement: single source of truth in Postgres; manual grant/revoke path (already promised as "backup to the backup"); deliberate, time-limited outage grace policy — a cancellation must never inherit fallback behavior (per Matt's plan).
  • Deploy-time fragility that exists right now: the build downloads ~28 assets from Webflow with a 120s urlopen each — a Webflow outage or URL change breaks deploys; and the deleted-fallback finding (§5) means a runtime Webflow failure blanks the world. Smallest fix: stop deleting dist/images (one plugin removal) and/or move assets to the app's own hosting before launch week.
  • Rollback: Netlify deploy history gives instant rollback for the front; the backend needs migration discipline + a documented rollback per pack law.
  • Observability: none exists; launch dashboard per Matt's plan is a Phase-2 deliverable.

9Security Assessment

  • P1 — the demo auth collects real passwords into a void. Users type email+password; it "works"; nothing is transmitted or stored server-side, but people reuse real passwords and the surface is publicly deployed. Before any launch-adjacent traffic: disable the form or wire it to the real backend. Also ensure the demo localStorage "session" can never be mistaken for entitlement by later code. raw_source
  • Secrets: repo is clean — no keys, no tokens (verified grep). The only hardcoded IDs are the public Webflow form/page IDs.
  • Credential hygiene (outside the repo): Netlify + Gmail passwords were distributed in a PDF; the Gmail is the root identity for GitHub and Netlify. Rotate both, enable 2FA, move to per-person access. (Passwords are not reproduced in this report.)
  • Form abuse: Netlify form has a honeypot; the Webflow form has nothing — bot signups will pollute the launch list. Consolidation (ST-6) is also the fix.
  • Supply chain: one devDependency (vite). About as small as an attack surface gets. package-lock.json integrity not audited.
  • Headers: nosniff + referrer policy present; no CSP (fine for a static site at this stage).
  • No PII is stored anywhere server-side today except the two email lists.

12Recommended First Tracer

Riskiest assumption capable of invalidating the plan: "Whop can take a regional-priced recurring payment and reliably tell our backend about it." Everything else assumes it.

The tracer: one real person → regional-priced Whop checkout (test mode) → signed webhook → idempotent entitlement grant in Postgres → real auth session behind Tiardt's existing sign-in UI → protected playback of a real video file inside the /watch stub on a phone → visible in a minimal admin view → then: cancel → entitlement expires at period end.

  • Systems crossed: Whop checkout + webhooks · database · identity/session · entitlement enforcement · video platform signed URL · the authored-file frontend seam · admin readout.
  • Why not alternatives: auth-first proves no money; comments-first isn't load-bearing; load-testing first has nothing to test; schema-first is a horizontal layer (forbidden by the pack).
  • Machine proof: webhook delivered twice grants once; out-of-order events converge; expired session → playback denied; revoked entitlement → denied within one minute; logs show each transition.
  • Human proof: pay on a phone with a non-US card, watch the stand-in Part 2, share the playback URL to a second logged-out device and watch it fail, cancel and confirm access survives to period end.
  • Expansion threshold: tracer passes → build Launch Core horizontally per the Build Map. Stop condition: if Whop cannot do per-country recurring pricing acceptably, stop and escalate the provider decision to Samuel the same day — that is a scope-level event, not an engineering detail.
