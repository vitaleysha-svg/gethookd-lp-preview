Page 1 — Signup / Login

  • Signup form (email + password). Password rule: minimum 10 characters, shown on the form
  • Signup error: This email is already registered — log in instead
  • After signup the user is signed in right away (no verify-email step) → land on the pricing page
  • Login form. Error copy exactly Wrong email or password — never "wrong password" (we don't reveal which)
  • "Too many attempts, wait a moment" state on login, signup AND forgot-password
  • Forgot password: enter email → ALWAYS show "check your email", even for unknown emails
  • Reset screen (from email link): password rule shown; error state This link has expired or was already used — request a new one (links work once, die after 30 min)
  • After successful reset: do NOT sign in — show "password updated, log in" → login (reset signs them out everywhere)
  • Session-expired: any page can hit it → send to login with "your session expired"

Page 2 — Pricing

  • Price display (backend-rendered, placeholder for now) + monthly/annual toggle + Join button
  • Join while signed out → route through signup/login and STRAIGHT back into checkout without losing the toggle choice (main buying path — smooth)
  • Join while signed in → backend returns a checkout link → redirect to it
  • Existing member opens the page → "You're already a member" linking to the videos (no Join button)
  • Loading + "something went wrong, try again" states
  • Return screen (new, important): after paying on Whop the buyer lands back on our site while payment confirms (a few seconds). Build "Setting up your membership…" that re-checks every few seconds until access turns on; fallback after ~1 min: "taking longer than expected — refresh or contact support"

Page 3 — Video Player

  • Locked (non-member → push to pricing) · loading · playing · error + retry
  • Link refresh: the access link dies after max 10 minutes. Quietly fetch a fresh one before it runs out so long videos never stop. If the refresh is refused mid-video, show the matching screen below
  • Can't-watch screens split by the reason the backend gives:
    · not signed in → send to login
    · never paid → locked screen, push to pricing
    · membership ended → "Your membership has ended — rejoin"
    · payment paused → "Payment issue — update your payment to keep watching"
    · access removed (refund/chargeback) → "Access removed — contact support"
  • Grace members (payment problem, still in their window) CAN watch — dismissible "payment problem, update your payment" banner over the player, never a block
  • Never store the video link (nothing saved, nothing in the URL). On refresh: re-check membership, fetch fresh

Page 4 — Profile

  • Status line for EVERY state:
    · active → Member — renews on [date]
    · canceled → Canceled — access until [date]
    · payment problem → Payment issue — access continues a few more days, update your payment (no date)
    · paused → Access paused — fix your payment to get back in
    · expired → Membership ended — rejoin
    · removed → Membership inactive — contact support
    · not a member → Not a member — join
  • Dates come as raw numbers from the backend; if missing, show the line without a date — never "Invalid Date"
  • Cancel button + confirmation showing the REAL returned date: "Canceled — you keep access until [date]" + a "billing system busy, try again" state
  • Resume button (only after a cancel), same busy/retry state
  • "Update payment" button for the payment-problem states — destination placeholder, will be confirmed
  • Log out button
  • Support: contact email link (address to be confirmed — placeholder)
  • Delete account: keep in the DESIGN, all copy placeholder (legal pending). For launch the confirm just opens an email to support. Do not wire it — no backend call exists yet

Global — all four pages

  • States everywhere: logged out · logged in unpaid · paid · loading · "something went wrong, try again"
  • Backend errors carry a short reference code — print it small on error screens ("ref: XYZ")
  • Every backend call sends credentials (cookie auth); pages only work on the real site address, not preview domains — plan testing accordingly
  • Mobile layouts of all four pages, including every error/locked/expired state, are part of the freeze
  • No change-password form in profile — forgot-password is the only path for now
